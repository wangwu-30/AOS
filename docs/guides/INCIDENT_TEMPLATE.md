# 故障复盘模板（Incident Template）

本文提供统一模板，用于新增真实故障条目。目标是让后续复盘可比较、可搜索、可沉淀。

## 使用方式

- 单次真实故障可以直接复制本模板到新的文档。
- 若属于 PA 链路问题，优先放到 `docs/guides/` 或 `docs/journal/` 的对应主题文档中。
- 若故障推动了不可逆设计调整，必须同步补 ADR 与 Spec。

## 模板

```md
# 标题

## 1. 基本信息

- 日期：
- 渠道：
- 影响范围：
- 发现方式：
- 当前状态：

## 2. 症状

- 用户可见现象：
- 终端/日志现象：
- 首次出现时间：
- 是否可稳定复现：

## 3. 影响

- 是否阻断主流程：
- 是否存在错误回复：
- 是否存在静默失败：
- 是否影响历史消息/重复发送/数据一致性：

## 4. 根因

- 直接根因：
- 深层根因：
- 为什么之前没发现：

## 5. 证据

- 关键日志：
- 关键 trace：
- 关键事件/出站文件：
- 相关代码路径：

## 6. 修复动作

- 代码修复：
- 文档修复：
- 配置/运维修复：

## 7. 验证

- 用什么方式验证：
- 覆盖了哪些回归：
- 仍然没覆盖什么：

## 8. 防再发

- 长期规则：
- 新增监控/日志：
- 是否需要 Admission Test：
- 是否需要规范更新：

## 9. 关联文档

- Spec：
- ADR：
- Changelog：
- 相关 runbook：
```

## 最低填写要求

以下字段不应留空：

- 症状
- 根因
- 证据
- 修复动作
- 验证
- 防再发

## 写作建议

- 不要只写“已修复”，要写清“为什么坏”。
- 不要只贴错误码，要贴足够区分根因的上下文。
- 不要只写单次补丁，要抽出长期规则。
- 如果故障暴露了静默失败，必须明确写出“为什么之前会静默”。
