## Summary（综合摘要）

目标（Goal）：引入最小 Skill Registry（技能注册表，Skill Registry）与内容寻址（content addressing）引用形态，使 `ExecuteRequest.skill_ref` 支持 `registry://<registry_id>`，并在本地（local-only）通过只读映射解析到 `skill_dir`，且不改变 ASVP 验签与 evidence/trace 回放语义。

统一口径（Consensus）：
- registry_id：基于 ASVP `manifest.json` 的 canonical bytes 做 `sha256`，生成稳定 `registry_id`（`rg_` 前缀 + 截断 hex）。
- 本地索引：`data/registry/index.json` 维护 `registry_id -> skill_dir` 映射；不引入网络下载/市场逻辑。
- 执行路径：LocalExecutor 在构造 `PackageRunRequest.skill_dir` 前解析 `registry://`；RemoteExecutor 不做本地解析（远端可自行解释 registry ref）。
- Fail-Closed：解析失败/缺映射/映射指向目录无法通过 ASVP verify 时，必须拒绝执行（不回退为 path，不静默降级）。

Bounded Spike（限界实验）建议（用于避免破坏执行路径）：
- Spike-REG1 仅改“解析层”：`registry://... -> Path(skill_dir)`；不改 `SkillPackageLoader` 的 ASVP verify 语义。
- Kill criteria：若为支持 registry 引入新的顶层字段或破坏现有 `mvp exec`/`mvp run-package` 输出稳定性，则回退为“registry 仅作为 rc-pack 的审计字段”，执行阶段暂不消费。
